# Uno Launcher v0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.2.0 with the default Uno image whose lights follow the engine, configurable home shortcuts, and Settings scroll retention.

**Architecture:** Car images are made offline (outside the repo) and bundled as two drawables; the home crossfades them by a pure `CarState.engineRunning`. Shortcuts are 3 saved strings resolved against the launcher-app list by a pure `resolveShortcut`. Settings scroll survives navigation by hoisting its `LazyListState` into `App()`.

**Tech Stack:** Kotlin, Jetpack Compose, Robolectric + Roborazzi tests; Python (rembg, Pillow, numpy) outside the repo for the image.

**Spec:** `docs/superpowers/specs/2026-11-14-v0.2.0-design.md`

## Global Constraints
- Same toolchain as v0.1.0: `./g`, minSdk 26, no new Gradle dependencies.
- Copy in pt-BR. Touch targets stay large (tile row height unchanged).
- No plate, no background and no personal path in the repo or APK.
- versionCode 2, versionName "0.2.0".

## Review Focus
- Saved shortcut whose app was uninstalled: tile still shows a name and tapping shows "não está instalado", no crash.
- Consis not installed (tablet): tile "Consis", tap shows "Consis não está instalado".
- Corrupt/short `shortcuts` pref (e.g. from a future version): falls back to defaults, no crash.
- Custom photo chosen: lights overlay is not drawn over it; "Usar o Uno padrão" deletes the file and the default returns.
- Link IGNITION_OFF / OFF / CONNECTING with stale rpm: lights stay off.
